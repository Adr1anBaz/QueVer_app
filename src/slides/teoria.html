Entender Apache Cordova

El problema que atiende, su contexto web y el recorrido de PhoneGap a Apache.

José Adrián Bazaldúa Huerta
Haili Ailin Ávila Ramírez
Universidad Iberoamericana

9 de noviembre de 2026

Abra con la pregunta central: cómo usar conocimientos web para crear aplicaciones móviles. Esta primera parte explica el contexto y la historia; la segunda parte abordará arquitectura, plugins y decisiones de uso.

Un problema de plataformas

01 / problema

Una misma idea móvil podía exigir equipos, lenguajes y herramientas distintos para cada sistema operativo.

El reto: llegar a más de una plataforma sin rehacer toda la interfaz.

  1. Una experiencia para cada sistema
  2. Código y herramientas diferentes
  3. Más tiempo de mantenimiento
  4. Necesidad de reutilizar

Fuente: Apache Cordova, Overview.

No afirme que una sola base elimina todo el trabajo específico. El problema es reducir duplicación en la interfaz y la lógica web; las plataformas siguen teniendo requisitos propios.

La web ya tenía una base común

02 / contexto

HTML, CSS y JavaScript eran tecnologías conocidas para construir interfaces y comportamiento en el navegador.

Una WebView lleva ese código web dentro de una aplicación para cada plataforma.

  1. HTML estructura la pantalla
  2. CSS define la presentación
  3. JavaScript responde a acciones
  4. La app se empaqueta por plataforma

Fuente: Apache Cordova, Overview.

Explique WebView como una ventana de navegador integrada, no como un navegador separado. Cordova permite que el código web se ejecute dentro de un contenedor de aplicación.

La necesidad: web + dispositivo

03 / motivación

Reutilizar código web no bastaba si la app no podía interactuar con capacidades del teléfono.

Cordova une tecnologías web con APIs del dispositivo.

  1. Sensores y estado de red
  2. Cámara y almacenamiento
  3. Interfaz web compartida
  4. Acceso mediante APIs compatibles

Fuente: Apache Cordova, Overview.

La idea no es convertir HTML en controles nativos automáticamente. Es ejecutar una app web y ofrecer enlaces a capacidades nativas cuando la aplicación las necesita.

2008: comienza PhoneGap

04 / Nitobi

PhoneGap surgió como proyecto de código abierto de Nitobi Software en 2008.

Su propuesta conectaba desarrollo web y aplicaciones móviles híbridas.

  1. Nitobi inicia PhoneGap
  2. Se publica como código abierto
  3. Se enfoca en apps híbridas
  4. Abre el camino del proyecto

Fuente primaria: Apache Cordova, “Goodbye PhoneGap” (2020).

Esta fecha procede del comunicado oficial de Apache Cordova. Presente PhoneGap como el origen histórico, no como el nombre actual del proyecto Apache.

2011: Adobe adquiere Nitobi

05 / transición

Adobe adquirió Nitobi en 2011 y, poco después, PhoneGap fue donado a la Apache Software Foundation.

La donación separó la tecnología base de una sola empresa.

  1. Adobe compra Nitobi
  2. PhoneGap continúa como marca
  3. La base se dona a Apache
  4. Empieza una nueva etapa

Fuente primaria: Apache Cordova, “Goodbye PhoneGap” (2020).

No sugiera que Adobe desapareció del día a día de inmediato. La idea clave es la transición de la tecnología hacia una fundación y un modelo de comunidad.

Callback se convierte en Cordova

06 / Apache

El proyecto entró a la incubadora de Apache en octubre de 2011 como Callback; el nombre pasó a ser Apache Cordova.

Apache aporta un gobierno abierto basado en comunidad y contribuciones.

  1. Octubre de 2011: incubación
  2. Nombre inicial: Callback
  3. Nombre del proyecto: Cordova
  4. Proyecto Apache establecido en 2012

Fuente primaria: Apache Foundation, Board history: Cordova.

Diga que Callback fue el nombre de incubación y Cordova el nombre adoptado por Apache. La cronología de la fundación registra la creación formal del proyecto Apache en octubre de 2012.

PhoneGap y Cordova no terminaron juntos

07 / diferencia clave

Adobe anunció el cierre de PhoneGap en 2020. Apache Cordova, como proyecto abierto mantenido por comunidad, continuó.

Cierre de PhoneGap no significa cierre de Apache Cordova.

  1. PhoneGap: producto y marca de Adobe
  2. 2020: Adobe anuncia su cierre
  3. Cordova: proyecto de Apache
  4. Su continuidad depende de su comunidad

Fuente primaria: Apache Cordova, “Goodbye PhoneGap” (14 ago. 2020).

Esta distinción evita el error más común de la historia del proyecto. El anuncio de 2020 afirma expresamente que Cordova seguía activo y mantenido; no use el cierre de PhoneGap como evidencia de que Cordova terminó.
