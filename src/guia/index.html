Antes de empezar

Necesitas Android Studio, un emulador configurado, internet y VS Code. Usa el emulador que ya tienes. No hace falta un teléfono ni instalar Xcode.

Comprueba que puedes instalar programas en la Mac y solicita tu clave OMDb antes de la clase. La primera compilación descarga dependencias y puede tardar.

Solicita tu clave de películas

  1. Abre OMDb · API Key. Elige la opción gratuita disponible, escribe tu correo y completa el formulario.
  2. Revisa tu correo y spam. Abre el enlace de activación que envía OMDb.
  3. Conserva tu clave. En la fase 1 la pondrás en www/js/config.local.js. No la pegues en el chat, GitHub ni capturas.
  4. Si el correo no llega, puedes completar la pantalla y SQLite mientras esperas; para buscar películas sí necesitarás activarla.

En cada fase

  1. Abre la fase que indique el expositor.
  2. Crea los archivos nuevos. En los que cambian, reemplaza todo el contenido.
  3. En VS Code: abre el archivo → ⌘A → ⌘V → ⌘S.
  4. Las líneas violetas con + muestran qué cambió. El botón copia el archivo completo, sin marcas.
  5. Ejecuta la app y haz la prueba de esa fase.

Si te atrasas, usa los archivos de la fase actual. Conserva tu clave y no desinstales la app.

Qué hace cada archivoindex.html: pantalla. index.css: estilos. index.js: acciones. db.js: consultas SQLite. Todos están dentro de www/; Cordova los incluye en la app Android.

Preparar la Mac

Abrir VS Code y su terminal

  1. En Finder, crea taller-cordova en el Escritorio. Si ya existe, comprueba que no contiene otro proyecto quever.
  2. En VS Code abre File → Open Folder y selecciona taller-cordova.
  3. Abre Terminal → New Terminal. Todos los comandos de la guía se ejecutan ahí, no en Debug Console ni en un archivo.

Resultado esperado: el Explorador de VS Code muestra taller-cordova. Abajo aparece una terminal, normalmente zsh, con el cursor listo.

Si falla: si no ves la terminal, vuelve a Terminal → New Terminal. Si VS Code pide confiar en la carpeta, acepta solo si es la que acabas de crear.

Ejecuta un bloque a la vez. Las salidas de ejemplo son ilustrativas: pueden cambiar rutas, versiones y tiempos. Los comandos cd, mkdir y export normalmente no imprimen nada.

VS Code · terminal integrada · comprobar Node
node --version

Resultado esperado: una versión compatible, por ejemplo v22.14.0. Node 22.9+ de la rama 22 o Node 20.17+ sirven para este taller.

Si falla: si dice command not found, instala Node con las instrucciones de abajo.

VS Code · terminal integrada · comprobar npm
npm --version

Resultado esperado: un número de versión, por ejemplo 10.9.2. No tiene que coincidir con el de Node.

Si falla: npm viene con Node. Revisa su instalación y reinicia VS Code.

VS Code · terminal integrada · localizar Java 17
/usr/libexec/java_home -V

Resultado esperado: una lista de JDK instalados. Debe incluir una versión 17 y su ruta. Puede haber otras versiones.

Si falla: si no aparece Java 17 o dice que no encuentra un runtime, instala Temurin JDK 17.

VS Code · terminal integrada · comprobar Gradle
gradle --version

Resultado esperado: un informe con Gradle, su versión y la JVM. El Gradle del sistema no tiene que coincidir con el que descargue Cordova.

Si falla: usa “Me falta Gradle”. Si el error menciona Java, configura JDK 17 en el bloque de variables y repite la consulta.

Referencia del taller: Cordova CLI 13.0.0, Android 15.1.0 y SQLite 7.0.0. Node 22.9 o superior dentro de la rama 22 es una opción compatible; Node 20.17+ también sirve para estas versiones. Usa JDK 17 con Cordova, aunque Android Studio utilice otro Java.

Me falta Node o Java 17
  1. Node: descarga el instalador de la rama 22 para macOS en nodejs.org. npm viene incluido.
  2. Java: descarga Temurin JDK 17 para macOS, instalador .pkg. Apple Silicon usa aarch64; Intel usa x64. Consulta  → Acerca de esta Mac para identificarla.
  3. Ejecuta los instaladores. Después cierra y abre VS Code, vuelve a abrir taller-cordova y crea una terminal integrada nueva.

Resultado esperado: el instalador confirma que terminó. Repite las consultas: Node y npm muestran sus versiones; la lista de JDK incluye Java 17.

Si falla: si la escuela pide una contraseña de administrador, solicita autorización. Si siguen sin aparecer las versiones, comprueba que reiniciaste VS Code.

Me falta Gradle

Si ya tienes Homebrew y permiso para instalar, usa esta opción:

VS Code · terminal integrada · solo si tienes Homebrew
brew install gradle

Resultado esperado: Homebrew termina la instalación o avisa que Gradle ya estaba instalado.

Si falla: si brew no existe, usa la alternativa siguiente. Si pide permisos que no tienes, consulta al expositor.

Sin Homebrew, descarga Gradle 8.14.2 en tu usuario. Elige solo una de las dos rutas. Ocupa más de 100 MB. Si aparece un error de Java, configura JDK 17 en el bloque de variables y vuelve a comprobar Gradle.

VS Code · terminal integrada · alternativa sin Homebrew
mkdir -p "$HOME/.local/gradle"
curl -fL https://services.gradle.org/distributions/gradle-8.14.2-bin.zip -o "$HOME/.local/gradle/gradle-8.14.2-bin.zip"
unzip -n "$HOME/.local/gradle/gradle-8.14.2-bin.zip" -d "$HOME/.local/gradle"
export PATH="$HOME/.local/gradle/gradle-8.14.2/bin:$PATH"
gradle --version

Resultado esperado: mkdir crea la carpeta sin mensaje; curl completa la descarga; unzip extrae los archivos o conserva los que ya existían; export no imprime nada; la última consulta muestra Gradle 8.14.2.

Si falla: si la descarga no termina, revisa internet. Si unzip dice que no es un ZIP válido, no continúes: vuelve a descargarlo. Si falla la JVM, configura Java 17 y repite gradle --version.

Mantén esta terminal abierta. No cambies las versiones de los archivos generados por Cordova.

Revisar el SDK en Android Studio

Abre Tools → SDK Manager si tienes un proyecto abierto, o More Actions → SDK Manager desde la bienvenida. Confirma:

  • SDK Platforms: Android 16 / API 36 para compilar.
  • SDK Tools: Build-Tools 36.x, Platform-Tools, Command-line Tools (latest) y Android Emulator.
  • Conserva la ruta de Android SDK Location. Normalmente es ~/Library/Android/sdk.

Resultado esperado: los componentes aparecen instalados. Si marcaste alguno nuevo, pulsa Apply y espera a que termine la descarga.

Si falla: si la descarga o las licencias quedan pendientes, resuélvelas antes de compilar. No necesitas descargar otra imagen si tu emulador ya funciona.

API 36 es el SDK para compilar; el emulador no necesita tener exactamente esa versión.

Configurar la terminal de VS Code

Vuelve a la misma terminal integrada. Ajusta ANDROID_HOME si SDK Manager muestra otra ruta.

VS Code · terminal integrada · configurar Java y Android
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/emulator:$PATH"
java -version
adb --version
sdkmanager --version

Resultado esperado: los tres export no imprimen nada. java -version indica 17; adb --version muestra Android Debug Bridge; sdkmanager --version muestra su versión.

Si falla: revisa Java 17, la ruta del SDK y Command-line Tools (latest). Si abres otra terminal, repite este bloque; también el PATH de Gradle o Cordova si los instalaste en tu usuario.

Opcional: conservar las variables para futuras sesiones

Abre ~/.zprofile en VS Code; créalo si no existe. Añade al final las tres líneas export del bloque anterior. No reemplaces su contenido. Guarda, ejecuta source ~/.zprofile en la terminal integrada y consulta java -version. Para la clase basta la configuración temporal.

Resultado esperado: source no muestra mensajes y la consulta de Java indica 17.

Si falla: revisa comillas, rutas y que guardaste el archivo. No borres las líneas que ya tenía.

Instalar Cordova

VS Code · terminal integrada · instalar la CLI
npm install -g cordova@13.0.0
cordova --version

Resultado esperado: npm termina la instalación y la segunda línea muestra 13.0.0. Pueden aparecer avisos de paquetes; no son lo mismo que un error.

Si falla: si ves EACCES o no reconoce cordova, consulta permisos de npm. No agregues sudo sin revisar la causa.

npm descarga Cordova; -g instala el comando para usarlo en distintas carpetas.

Crear el proyecto

Usa la misma terminal de VS Code. Si taller-cordova ya contiene otro quever, no lo sobrescribas: consulta al expositor para elegir otra carpeta.

VS Code · terminal integrada · crear quever/
mkdir -p ~/Desktop/taller-cordova
cd ~/Desktop/taller-cordova
cordova create quever com.ejemplo.quever QueVer
cd quever

Resultado esperado: mkdir y cd no muestran mensajes. Cordova informa que creó el proyecto. En el Explorador aparece quever/ con config.xml, package.json y www/. La terminal queda dentro de quever.

Si falla: si indica que la carpeta ya existe o no está vacía, no la borres. Si el último cd falla, revisa primero si Cordova terminó de crearla.

Qué hace el comandocreate genera la app; quever es la carpeta; com.ejemplo.quever es el identificador Android; QueVer es el nombre visible.
VS Code · terminal integrada · dentro de quever/
pwd
ls

Resultado esperado: pwd muestra una ruta que termina en /taller-cordova/quever. ls incluye config.xml, package.json y www.

Si falla: vuelve a entrar con cd ~/Desktop/taller-cordova/quever. No ejecutes los siguientes comandos desde otra carpeta.

VS Code · terminal integrada · añadir Android y SQLite
cordova platform add android@15.1.0
cordova plugin add cordova-sqlite-storage@7.0.0
cordova requirements android

Resultado esperado: Cordova añade la plataforma y el plugin. Aparecen platforms/android/ y plugins/. El diagnóstico final indica installed para Java JDK, Android SDK, Android target y Gradle.

Si falla: corrige el requisito que marque como ausente. Si menciona licencias, ejecuta el siguiente bloque y repite cordova requirements android.

VS Code · terminal integrada · solo si faltan licencias
sdkmanager --licenses

Resultado esperado: aparecen licencias para revisar, o un aviso de que ya están aceptadas. Al aceptar las pendientes, el proceso termina sin error.

Si falla: si no reconoce sdkmanager, revisa Command-line Tools y el PATH de la terminal. Acepta los términos solo si estás de acuerdo.

Iniciar el emulador en Android Studio

  1. Abre Android Studio. No necesitas abrir QueVer ahí.
  2. Desde la bienvenida: More Actions → Virtual Device Manager (en algunas versiones aparece como Device Manager).
  3. Si tienes un proyecto abierto: Tools → Device Manager.
  4. Busca el dispositivo que ya usan en clase y pulsa ▶. Si ya está encendido, no lo inicies otra vez.

Resultado esperado: se abre una ventana de teléfono. Espera a que aparezca la pantalla de Android y puedas desbloquearla.

Si falla: si no hay dispositivos en la lista, consulta al expositor antes de descargar una imagen. Si sigue arrancando, espera; no pulses ▶ de nuevo.

VS Code · terminal integrada · comprobar el emulador
adb devices

Resultado esperado: una salida similar a esta. El número del emulador puede variar.

List of devices attached
emulator-5554    device

Si falla: si la lista está vacía, inicia el emulador desde Android Studio. Si dice offline, espera a que termine de arrancar y repite el comando.

VS Code · terminal integrada · ejecutar desde quever/
cordova run android --emulator

Resultado esperado: la compilación termina con BUILD SUCCESSFUL y Cordova instala y abre su app inicial en el emulador. La primera vez puede tardar por las descargas.

Si falla: si la compilación termina pero no abre la app, revisa adb devices. Si aparece BUILD FAILED, revisa el primer error y la sección Resolver errores.

Editar en VS Code

  1. En el Explorador, expande quever. Mantén abierta la carpeta taller-cordova; no necesitas cambiar de ventana.
  2. Edita quever/www/ y quever/config.xml. No edites platforms/android/.
  3. Para crear un archivo, pulsa con el botón derecho en su carpeta → New File. Escribe el nombre indicado en la fase.
  4. Para reemplazarlo: ⌘A, pega el archivo completo con ⌘V y guarda con ⌘S.

Resultado esperado: el archivo aparece en la ruta indicada. Al guardar, desaparece el punto de cambios pendientes de su pestaña. La app aún no cambia: debes volver a ejecutarla.

Si falla: revisa la carpeta y el nombre exactos; evita duplicados como index.js.txt. Si abriste otra terminal, vuelve a configurar sus variables y entra a quever/.

Después de cada fase, guarda los archivos y ejecuta cordova run android --emulator desde quever/. No uses Live Server: abrir el HTML en un navegador no ejecuta los plugins Android.

Resolver errores

¿En qué carpeta ejecuto Cordova?

En la carpeta que contiene config.xml, package.json y www/. Para esta receta: cd ~/Desktop/taller-cordova/quever. Consulta pwd y ls si no estás seguro.

No reconoce node, npm o cordova / error EACCES

Después de instalar Node, reinicia VS Code y abre una terminal integrada nueva. Si npm install -g falla por permisos, puedes instalar Cordova en tu usuario:

VS Code · terminal integrada · alternativa sin sudo
npm install -g --prefix "$HOME/.cordova-cli" cordova@13.0.0
export PATH="$HOME/.cordova-cli/bin:$PATH"
cordova --version

Resultado esperado: npm instala la CLI sin permisos de administrador; export no muestra nada y la última línea imprime 13.0.0.

Si falla: revisa conexión y mensajes de npm. Si la escuela bloquea las instalaciones, pide autorización o trabaja en pareja.

Repite este export si abres otra terminal.

Java incorrecto o ANDROID_HOME no encontrado

Vuelve a las tres variables de Preparar la Mac, confirma la ubicación real en SDK Manager y ejecuta java -version. Debe usar 17. Después, dentro de quever, repite cordova requirements android.

Falta target Android, Build-Tools, sdkmanager o licencias

Instala API 36, Build-Tools 36.x y Command-line Tools (latest) desde SDK Manager. Si sdkmanager no aparece, revisa cmdline-tools/latest/bin dentro de tu SDK y repite las variables de sesión. Para licencias: sdkmanager --licenses, revisando sus términos.

No aparece el emulador o hay varios destinos

Abre Device Manager, inicia un solo AVD y espera a que arranque. Consulta adb devices y usa normalmente cordova run android --emulator. Si necesitas elegir uno ya encendido, copia su identificador de ADB (por ejemplo, emulator-5554) en cordova run android --emulator --target=emulator-5554, ajustándolo a tu lista. El nombre del AVD (por ejemplo, Pixel_4) no es ese identificador: puede hacer que Cordova intente arrancar otra instancia y falle por duplicado.

Gradle descarga mucho, tarda o falla

La primera ejecución descarga la distribución del proyecto y bibliotecas. Revisa que la red permita Google Maven, Maven Central y Gradle; conserva el mensaje completo del primer error. No cambies versiones dentro de platforms/android. Comprueba gradle --version y Java 17. Si el fallo es red, no se resuelve pegando otro checkpoint.

SQLite no disponible o pantalla “Preparando…”

No abras el HTML en el navegador: ejecuta la app Android. Desde quever consulta cordova plugin ls; debe incluir cordova-sqlite-storage 7.0.0. Si falta, agrégalo con cordova plugin add cordova-sqlite-storage@7.0.0 y vuelve a ejecutar. Comprueba que cordova.js, db.js e index.js están referenciados en el HTML de la fase.

La búsqueda falla o dice “Invalid API key”

Abre el enlace de activación del correo OMDb. Comprueba que www/js/config.local.js contiene una sola declaración con tu clave entre comillas y sin espacios adicionales. Guarda, recompila y busca Inception. No publiques la URL con tu clave. Un límite de cuota o una caída de OMDb no se arregla reinstalando Cordova.

Guardé archivos pero la pantalla no cambia / me atrasé

Verifica que editaste quever/www/, no platforms/android/, guarda todos los archivos y ejecuta otra vez cordova run android --emulator. Para recuperarte, copia los archivos completos de la fase actual, incluyendo los que están en “Sin cambios · recuperación”. Conserva tu clave. No desinstales ni borres quever.db.

Ver el error en la consola

Con QueVer abierto en el emulador, abre chrome://inspect/#devices en Chrome de la Mac. Pulsa “inspect” en su WebView y revisa Console. No compartas capturas con tu clave.
