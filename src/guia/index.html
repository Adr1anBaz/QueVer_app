Antes de empezar

Necesitas una Mac con Android Studio, un emulador que ya funcione, conexión a internet y un editor como Visual Studio Code. No necesitas teléfono, Xcode ni otra imagen de Android si tu emulador ya abre.

Preparación previa recomendada: comprueba permisos de instalación en la Mac de la escuela y solicita tu clave OMDb antes de la clase. La primera compilación descarga dependencias; 120 minutos no garantizan terminar instalaciones desde cero.

Solicita tu clave de películas

  1. Abre OMDb · API Key. Elige la opción gratuita disponible, escribe tu correo y completa el formulario.
  2. Revisa tu correo y spam. Abre el enlace de activación que envía OMDb.
  3. Conserva tu clave. En la fase 1 la pondrás en www/js/config.local.js. No la pegues en el chat, GitHub ni capturas.
  4. Si el correo no llega, puedes completar la pantalla y SQLite mientras esperas; para buscar películas sí necesitarás activarla.

Así se sigue cada fase

  1. Abre únicamente la fase que indique el expositor.
  2. Lee el mapa de archivos: crea los nuevos y reemplaza todo el contenido de los que cambiaron.
  3. En VS Code: abre el archivo indicado → ⌘A → pega con ⌘V → guarda con ⌘S. Si es nuevo, créalo en la ruta exacta.
  4. El fondo violeta y el signo + explican las diferencias. El botón copia el archivo completo, sin números ni marcas.
  5. Ejecuta la prueba Android y compara el resultado antes de avanzar.

No descargues la última fase para empezar. Si te atrasas, recupera los archivos completos de la fase actual, sin tocar tu clave ni desinstalar la app.

El mapa mentalwww/index.html es la pantalla; www/css/index.css su apariencia; www/js/index.js sus acciones; www/js/db.js habla con SQLite. Cordova los empaqueta dentro de una app Android.

Prepara la Mac, no la reinstales

Abre Terminal desde Spotlight. Estos primeros comandos consultan lo instalado. Si uno dice command not found, instala solo ese faltante.

Terminal · puedes ejecutarlo desde cualquier carpeta
node --version
npm --version
/usr/libexec/java_home -V
gradle --version

Referencia del taller: Cordova CLI 13.0.0, Android 15.1.0 y SQLite 7.0.0. Node 22.9 o superior dentro de la rama 22 es una opción compatible; Node 20.17+ también sirve para estas versiones. Usa JDK 17 con Cordova, aunque Android Studio utilice otro Java.

Me falta Node o Java 17
  1. Node: descarga el instalador de la rama 22 para macOS en nodejs.org. Si la escuela administra el software, solicita autorización en lugar de cambiarlo por tu cuenta. npm viene incluido.
  2. Java: descarga Temurin JDK 17 para macOS, instalador .pkg. Apple Silicon usa aarch64; Intel usa x64. Consulta  → Acerca de esta Mac para identificarla.
  3. Termina la instalación y abre una Terminal nueva. Vuelve a consultar las versiones.

Si ya usas Homebrew y tienes permisos, Java 17 también puede instalarse con brew install --cask temurin@17. No necesitas instalar Homebrew solo para Java.

Me falta Gradle

Si brew --version funciona y tienes permiso, ejecuta:

Solo si falta Gradle y ya existe Homebrew
brew install gradle

Sin Homebrew: descarga la distribución binary-only de Gradle y descomprímela en una carpeta de tu usuario. En Terminal escribe export PATH=", pega la ruta de su carpeta bin y termina con :$PATH". Comprueba gradle --version. El Gradle del sistema arranca el proceso; Cordova descarga con su wrapper la versión del proyecto. No fuerces su versión editando archivos generados.

Conecta Terminal con Java y Android

En Android Studio abre Tools → SDK Manager (o More Actions → SDK Manager en la bienvenida). Confirma:

  • SDK Platforms: Android 16 / API 36 para compilar.
  • SDK Tools: Build-Tools 36.x, Platform-Tools, Command-line Tools (latest) y Android Emulator.
  • Conserva la ruta de Android SDK Location. Normalmente es ~/Library/Android/sdk.

API 36 es el SDK de compilación; no exige que tu dispositivo virtual tenga exactamente esa versión. Reutiliza el emulador existente.

Terminal · configura esta sesión; ajusta ANDROID_HOME si tu ruta es distinta
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/emulator:$PATH"
java -version
adb --version
sdkmanager --version

Resultado: Java indica 17 y los otros dos comandos muestran su versión. Mantén esta Terminal abierta durante la práctica. Si abres otra, vuelve a ejecutar estas variables.

Opcional: conservar las variables para futuras sesiones

Abre tu archivo ~/.zprofile en el editor; créalo si no existe. Añade al final únicamente las tres líneas export anteriores. No reemplaces su contenido. Guarda, ejecuta source ~/.zprofile y consulta java -version. Para hoy basta la configuración temporal.

Instala Cordova

Terminal · instalación de la herramienta
npm install -g cordova@13.0.0
cordova --version

npm descarga la herramienta; -g la deja disponible fuera de una carpeta particular. Espera que indique 13.0.0. Si aparece EACCES, no añadas sudo a ciegas: revisa permisos de npm.

Primero: una app abierta en Android

En Terminal, crea una carpeta de trabajo nueva. Si ya existe quever en ella, elige otra carpeta vacía; no sobrescribas tu trabajo anterior.

Terminal · creación del taller en tu Escritorio
mkdir -p ~/Desktop/taller-cordova
cd ~/Desktop/taller-cordova
cordova create quever com.ejemplo.quever QueVer
cd quever

Qué acabamos de hacercreate genera la app. El primer quever es la carpeta; com.ejemplo.quever es el identificador Android; QueVer es el nombre visible. Para esta práctica todos pueden usarlo en emuladores separados.
Terminal · desde quever/; puede descargar dependencias
cordova platform add android@15.1.0
cordova plugin add cordova-sqlite-storage@7.0.0
cordova requirements android

Confirma que Java, SDK, target Android y Gradle aparecen disponibles. Si faltan licencias, ejecuta lo siguiente y revisa sus términos antes de aceptarlas:

Solo si hay licencias pendientes
sdkmanager --licenses

Abre Android Studio → Device Manager e inicia un solo dispositivo virtual con ▶. Espera a que muestre la pantalla de Android. No necesitas abrir el proyecto en Android Studio.

Terminal · desde quever/
cordova run android --emulator

No avances hasta ver esto

La app inicial de Cordova abre en el emulador. La primera compilación puede descargar Gradle y bibliotecas; las siguientes suelen ser más rápidas.

Abre Desktop/taller-cordova/quever con VS Code → File → Open Folder. Editaremos www/ y config.xml, nunca los archivos generados de platforms/android/.

Después de cada fase: guarda todos los archivos y ejecuta de nuevo cordova run android --emulator desde esta misma carpeta. No basta con refrescar una pestaña ni abrir www/index.html en Safari.

1Pantalla y SQLite35–45 min · base de la aplicación

Una pantalla conectada al dispositivo

Al terminar tendrás una pantalla QueVer y una base local lista. Todavía no habrá buscador ni películas.

Para entender este bloqueAndroid abre una WebView con nuestro HTML. cordova.js conecta JavaScript con el contenedor. Esperamos deviceready antes de llamar al plugin SQLite. initDB() crea la tabla movies solo si no existe; por eso volver a abrir la app no borra tus datos.

Crea o reemplaza estos archivos

La ruta www/ empieza dentro de tu carpeta quever. En www/js/config.local.js, sustituye TU_API_KEY por tu clave OMDb entre comillas. Si aún no llegó, deja el marcador por ahora.

Comprueba la fase 1

Guarda y ejecuta cordova run android --emulator.

  1. Ves “QueVer” y “La base de tu catálogo está lista”.
  2. El estado cambia a “Tu catálogo está listo para recibir películas”. Esto confirma que terminó la creación de la tabla.
  3. Cierra y vuelve a abrir la app: el mensaje listo reaparece.

Todavía no: buscar, guardar, editar ni recomendar. Creamos el esquema completo de datos para evitar migraciones durante la clase, pero las operaciones llegarán cuando las usemos.

Si SQLite no abre, revisa el plugin en solución de problemas.Continuar con fase 2
2Buscar películas45–60 min · API, eventos y resultados

Del título a los resultados

Al terminar podrás buscar Inception y abrir el detalle de una película. Activa tu clave OMDb antes de probar.

Recorre el datoEl formulario dispara submit → searchMovies() lee el título → requestOmdb() usa fetch por HTTPS → OMDb devuelve JSON → renderSearchResults() crea los elementos de la pantalla. “Ver detalle” consulta el identificador IMDb. Esta búsqueda es web; SQLite todavía no guarda el resultado.

Conserva www/js/config.local.js. No pegues la plantilla otra vez. Si no había clave, abre ahora ese archivo y sustituye solo el marcador.

Comprueba la fase 2

Guarda y ejecuta cordova run android --emulator.

  1. Busca Inception; deben aparecer resultados. Esto también comprueba tu clave y su activación.
  2. Pulsa “Ver detalle”: aparecen título, año y sinopsis.
  3. Busca sin escribir: aparece un aviso para introducir un título.
  4. Si OMDb dice “Invalid API key”, vuelve al correo de activación y verifica tu archivo de clave.

Todavía no: guardar películas ni opiniones. El detalle explica que el guardado llega en la siguiente fase.

La búsqueda requiere internet; la clave gratuita tiene cuota.Continuar con fase 3
3Guardar una película60–75 min · de la API a SQLite

Tu primera película guardada

Ahora decides si quieres verla o ya la viste. Una vista puede llevar calificación y opinión.

De internet al almacenamiento localEl detalle trae datos de OMDb → saveMovie() añade estado y opinión → insertMovie() envía SQL al plugin → SQLite guarda el registro → consultamos los datos y actualizamos la lista. Los ? de SQL son parámetros: separan la consulta de los valores. imdb_id es único para impedir duplicados.

Comprueba la fase 3

Guarda y ejecuta cordova run android --emulator.

  1. Busca una película, abre el detalle y pulsa “La quiero ver”. Debe aparecer en el listado.
  2. Guarda otra con “Ya la vi”, calificación y opinión.
  3. Intenta guardar la primera otra vez: debe avisar que ya existe, sin sobrescribirla.
  4. Cierra y vuelve a abrir QueVer desde Android. Las películas deben seguir guardadas.

Todavía no: catálogo por tarjetas, editar ni eliminar. No desinstales la app: eso sí puede borrar su base.

Los datos están en el emulador, no en OMDb ni en esta página.Continuar con fase 4
4Ordenar el catálogo75–87 min · vistas y pendientes

Los mismos datos, una vista más útil

Separamos películas pendientes y vistas, añadimos tarjetas y abrimos el detalle de lo guardado.

No estamos creando otra basegetMoviesByStatus() lee los registros de SQLite. loadCatalog() pide los dos estados y dibuja cada sección. La portada muestra hasta cinco por estado y “Ver más” muestra todos los registros ya consultados; no descarga otra página de OMDb.

Comprueba la fase 4

Guarda y ejecuta cordova run android --emulator.

  1. Las películas de la fase anterior siguen ahí, separadas por estado.
  2. Abre una tarjeta: ves su detalle guardado y, cuando corresponde, tu opinión.
  3. Si tienes más de cinco en un estado, “Ver más” permite ver el resto. Con menos, no debe aparecer ese enlace.

Todavía no: modificar o borrar. Cambiamos la presentación, no la identidad de los registros.

No debes reescribir tu clave ni reinstalar SQLite.Continuar con fase 5
5Editar y eliminar87–99 min · completar el CRUD

El catálogo ya se puede mantener

Corrige opiniones, cambia de pendiente a vista o elimina una película con confirmación.

CRUD en nuestra appCreate: INSERT; Read: SELECT; Update: UPDATE; Delete: DELETE. El identificador IMDb dice qué registro cambiar. Primero esperamos el resultado de SQLite y después mostramos el éxito o actualizamos las tarjetas.

Comprueba la fase 5

Guarda y ejecuta cordova run android --emulator.

  1. Abre una película vista y edita su opinión o calificación. Al volver a abrirla, conserva el cambio.
  2. Marca una pendiente como vista: cambia de sección.
  3. Pulsa eliminar y cancela: la película permanece.
  4. Repite y confirma: desaparece. Reinicia la app y comprueba el estado final.

Todavía no: recomendación. El CRUD ya está completo.

Eliminar un registro no desinstala la app ni borra todo el catálogo.Continuar con fase 6
6Recomendar una película99–107 min · reutilizar lo construido

Una nueva entrada, el mismo guardado

El botón “Recomiéndame una” busca una película en OMDb y permite guardarla con las acciones que ya conoces.

No es inteligencia artificialElegimos una palabra de búsqueda al azar, consultamos OMDb y elegimos un resultado. Pedimos su detalle antes de abrir el cuadro. saveRandomMovie() reutiliza saveMovie(); no inventamos otra base ni otro guardado.

Comprueba la fase 6

Guarda y ejecuta cordova run android --emulator.

  1. Pulsa “Recomiéndame una”: aparece un título, sus datos y opciones de guardado.
  2. Guárdala como pendiente o vista. Debe aparecer en el catálogo.
  3. Cierra otra recomendación sin guardar: el catálogo no cambia.
  4. Sin internet, la consulta avisa del fallo en lugar de mostrar una recomendación vacía.
La interfaz web, el plugin y Android ya trabajan juntos.Hacer la comprobación final

Demuestra que es tu app

  1. Busca una película y guárdala.
  2. Edita su opinión y cierra la app desde la vista de aplicaciones recientes de Android.
  3. Ábrela otra vez desde su icono. La película y tu cambio siguen ahí.
  4. Sin red, comprueba que puedes consultar lo ya guardado; buscar y recomendar sí necesitan internet.
  5. Explica: ¿qué parte ejecuta la WebView?, ¿qué hace el plugin?, ¿dónde viven los datos?

Lo que construiste

Una app Android con interfaz HTML/CSS/JavaScript, consulta HTTP a OMDb y almacenamiento SQLite nativo mediante Cordova.

Opcional: instalarla en tu teléfono Android

Conecta un cable de datos, activa Opciones de desarrollador → Depuración USB y acepta la autorización en el teléfono. En Mac no suele hacer falta un driver adicional.

Comprobar conexión del teléfono
adb devices

Debe aparecer como device, no unauthorized.

Desde quever/ · alternativa al emulador
cordova run android --device

El teléfono tendrá su propia base vacía; no recibe automáticamente lo guardado en el emulador.

Si algo falla, vuelve a este punto

¿En qué carpeta ejecuto Cordova?

En la carpeta que contiene config.xml, package.json y www/. Para esta receta: cd ~/Desktop/taller-cordova/quever. Consulta pwd y ls si no estás seguro.

No reconoce node, npm o cordova / error EACCES

Abre una Terminal nueva después de instalar Node. Si npm install -g falla por permisos, no cambies permisos de todo el sistema. Puedes instalar la CLI en una carpeta de tu usuario:

Alternativa sin sudo para instalar Cordova
npm install -g --prefix "$HOME/.cordova-cli" cordova@13.0.0
export PATH="$HOME/.cordova-cli/bin:$PATH"
cordova --version

Esta ruta también debe exportarse en cada Terminal nueva. Si la escuela bloquea descargas o instalaciones, pide autorización o trabaja en pareja; un comando no evita una restricción administrativa.

Java incorrecto o ANDROID_HOME no encontrado

Vuelve a las tres variables de Preparar la Mac, confirma la ubicación real en SDK Manager y ejecuta java -version. Debe usar 17. Después, dentro de quever, repite cordova requirements android.

Falta target Android, Build-Tools, sdkmanager o licencias

Instala API 36, Build-Tools 36.x y Command-line Tools (latest) desde SDK Manager. Si sdkmanager no aparece, revisa cmdline-tools/latest/bin dentro de tu SDK y repite las variables de sesión. Para licencias: sdkmanager --licenses, revisando sus términos.

No aparece el emulador o hay varios destinos

Abre Device Manager, inicia un solo AVD y espera a que arranque. Consulta adb devices y usa normalmente cordova run android --emulator. Si necesitas elegir uno ya encendido, copia su identificador de ADB (por ejemplo, emulator-5554) en cordova run android --emulator --target=emulator-5554, ajustándolo a tu lista. El nombre del AVD (por ejemplo, Pixel_4) no es ese identificador: puede hacer que Cordova intente arrancar otra instancia y falle por duplicado.

Gradle descarga mucho, tarda o falla

La primera ejecución descarga la distribución del proyecto y bibliotecas. Revisa que la red permita Google Maven, Maven Central y Gradle; conserva el mensaje completo del primer error. No cambies versiones dentro de platforms/android. Comprueba gradle --version y Java 17. Si el fallo es red, no se resuelve pegando otro checkpoint.

SQLite no disponible o pantalla “Preparando…”

No abras el HTML en el navegador: ejecuta la app Android. Desde quever consulta cordova plugin ls; debe incluir cordova-sqlite-storage 7.0.0. Si falta, agrégalo con cordova plugin add cordova-sqlite-storage@7.0.0 y vuelve a ejecutar. Comprueba que cordova.js, db.js e index.js están referenciados en el HTML de la fase.

La búsqueda falla o dice “Invalid API key”

Abre el enlace de activación del correo OMDb. Comprueba que www/js/config.local.js contiene una sola declaración con tu clave entre comillas y sin espacios adicionales. Guarda, recompila y busca Inception. No publiques la URL con tu clave. Un límite de cuota o una caída de OMDb no se arregla reinstalando Cordova.

Guardé archivos pero la pantalla no cambia / me atrasé

Verifica que editaste quever/www/, no platforms/android/, guarda todos los archivos y ejecuta otra vez cordova run android --emulator. Para recuperarte, copia los archivos completos de la fase actual, incluyendo los que están en “Sin cambios · recuperación”. Conserva tu clave. No desinstales ni borres quever.db.

Quiero inspeccionar el error real

En Chrome de la Mac abre chrome://inspect/#devices con el emulador y QueVer abiertos. Inspecciona la WebView y revisa Console. No compartas capturas que expongan tu clave. Para confirmar el catálogo, usa primero las pruebas visibles de cada fase; un log aislado no demuestra todo el recorrido.
