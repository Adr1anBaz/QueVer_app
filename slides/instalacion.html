Instalar Apache Cordova

Del entorno web al comienzo de la preparación de Android.

José Adrián Bazaldúa Huerta
Haili Ailin Ávila Ramírez
Universidad Iberoamericana

9 de noviembre de 2026

Presenten el objetivo: ordenar las herramientas necesarias antes de crear o preparar una app. Esta primera parte llega hasta el inicio del entorno Android; los comandos son instrucciones, no pruebas realizadas.

¿Qué vamos a preparar?

01 / recorrido

Una app Cordova parte de código web y después se prepara para cada plataforma.

  1. Node.js y npm
  2. Cordova CLI
  3. Proyecto base
  4. Entorno Android

Fuente: Apache Cordova, guía CLI y estructura de proyecto.

Enfatiza el orden. Node y npm permiten instalar la CLI; la CLI crea el proyecto; Android se prepara después. No son cuatro instalaciones independientes ni se compila nada en esta exposición.

Capas que no conviene confundir

02 / requisitos

CLI crea y organiza el proyecto.

Plataforma aporta las herramientas de Android o iOS.

  1. Node.js ≥ 20.17.0
  2. Cordova CLI 13.x
  3. Android: JDK + SDK
  4. iOS: solo en macOS

Fuente: Apache Cordova, instalación CLI; guías Android e iOS.

Aclara que las versiones pertenecen a capas distintas. Tener Cordova CLI no significa que Android o iOS ya estén listos. iOS se cubrirá en la segunda parte del deck.

Primero: Node.js y npm

03 / base

npm acompaña a Node.js y permite instalar la herramienta de Cordova.

Para CLI 13.x: Node.js 20.17.0 o posterior.

  1. Instalar Node.js compatible
  2. Abrir una terminal nueva
  3. Consultar versiones

Fuente: Apache Cordova, instalación de la CLI.

Menciona que npm se instala con Node.js. Las consultas sugeridas son node --version y npm --version; mostrar una versión no demuestra que Android o un proyecto estén configurados.

Después: Cordova CLI

04 / herramienta

La CLI es el programa de terminal que crea y administra la estructura Cordova.

npm install -g cordova

  1. Instalar globalmente
  2. Consultar cordova --version
  3. Crear el proyecto desde una carpeta elegida

Fuente: Apache Cordova, instalación de la CLI.

Explica el -g: deja disponible el comando cordova en distintas carpetas. La versión de la CLI es una consulta; no verifica plataformas, SDKs ni plugins.

Crear la carpeta de la app

05 / proyecto

cordova create reúne el código web y la configuración inicial.

cordova create quever com.ejemplo.quever QueVer

  1. quever: carpeta
  2. com.ejemplo.quever: identificador
  3. QueVer: nombre visible

Fuente: Apache Cordova, guía CLI.

Descompón los tres argumentos. com.ejemplo.quever es solo un ejemplo: debe sustituirse por un identificador único antes de distribuir. Crear el proyecto todavía no instala Android ni iOS.

Cuatro archivos para ubicarse

06 / estructura

Reconocer la estructura evita editar por accidente contenido generado por una plataforma.

  1. www/ · HTML, CSS y JavaScript
  2. config.xml · preferencias Cordova
  3. package.json · dependencias
  4. .gitignore · si la plantilla lo crea

Fuente: Apache Cordova, estructura de proyecto.

Relaciona www con la interfaz web. config.xml contiene nombre e identificador; package.json lista dependencias. Aclara que .gitignore depende de la plantilla y no debe prometerse siempre.

Android empieza fuera del proyecto

07 / entorno

Antes de agregar la plataforma se prepara el conjunto de herramientas nativas.

Referencia para cordova-android 15.x.

  1. JDK 17
  2. Android Studio
  3. Android SDK
  4. Gradle y licencias

Fuente: Apache Cordova, guía de Android; matriz técnica 15.0.x.

Introduce que la guía técnica publicada detalla 15.0.x, mientras 15.1.0 está anunciado como lanzamiento. Por eso se usan estos requisitos como referencia, no como una prueba de compatibilidad local.

Android Studio instala el SDK

08 / SDK

En Tools › SDK Manager se eligen las piezas que usará la plataforma.

Guardar la ruta del SDK: se usará como ANDROID_HOME.

  1. API 36
  2. Build-Tools 36.x
  3. Platform-Tools
  4. Command-line Tools

Fuente: Apache Cordova, guía de Android (matriz 15.0.x).

Cierra esta parte con la idea práctica: Android Studio facilita instalar el SDK, pero hay que conservar su ubicación. En la continuación se verán variables, rutas, licencias y la plataforma Android. El emulador es opcional y no se configura aquí.

Conectar Java y el SDK

09 / rutas

La terminal necesita ubicar las herramientas instaladas fuera del proyecto.

JAVA_HOME y ANDROID_HOME apuntan a esas ubicaciones.

  1. Definir las variables según el sistema
  2. Añadir herramientas al Path
  3. Abrir una terminal nueva
  4. Consultar las rutas configuradas

Fuente: Apache Cordova, guía de Android.

Explique que estas rutas conectan la terminal con JDK y SDK. En macOS se suelen declarar en la configuración de zsh; en Windows, en Variables de entorno. Los comandos para consultar rutas son instrucciones: no se muestran resultados de esta computadora.

Licencias y plataforma Android

10 / preparar

Con el entorno localizado, se aceptan las licencias del SDK y se incorpora Android al proyecto.

cordova platform add android@15.1.0

  1. Revisar licencias del SDK
  2. Agregar la plataforma
  3. Dejar que Cordova genere sus archivos
  4. No editar platforms/android a mano

Fuente: Apache Cordova, guías Android y CLI; anuncio cordova-android 15.1.0.

La licencia corresponde al SDK de Android, no a Cordova. Al agregar la plataforma aparecen archivos generados: el trabajo diario sigue en www y config.xml. El número 15.1.0 es una versión publicada, no una versión instalada o verificada aquí.

Diagnosticar antes de compilar

11 / comprobar

La CLI puede señalar requisitos faltantes antes de intentar preparar una salida nativa.

cordova requirements android

  1. Corregir rutas o componentes faltantes
  2. Preparar el proyecto
  3. Compilar cuando el entorno esté listo
  4. Usar emulador o dispositivo por separado

Fuente: Apache Cordova, guías CLI y Android.

Diga que requirements ayuda a detectar dependencias, pero no sustituye una prueba funcional. Build crea artefactos nativos y run los despliega en un destino elegido; son etapas distintas. No se ejecutó ninguno de estos comandos para esta presentación.

SQLite es una decisión opcional

12 / plugin

Cordova no exige SQLite. Una app lo añade cuando necesita almacenamiento local mediante un plugin.

cordova-sqlite-storage es un ejemplo, no un requisito.

  1. Definir la necesidad de datos locales
  2. Revisar plataforma y permisos
  3. Agregar y documentar el plugin
  4. Probarlo en cada plataforma objetivo

Fuente: Apache Cordova, arquitectura de plugins; package.json de QueVer.

Conecte el ejemplo QueVer: su package.json declara cordova-sqlite-storage 7. Eso no demuestra que esté instalado ni que funcione en Android o iOS. Cada plugin agrega dependencias y debe validarse para la plataforma y la versión elegidas.

iOS requiere macOS y Xcode

13 / entorno iOS

La ruta iOS se prepara en una Mac con la aplicación completa de Xcode.

Para cordova-ios 8.x: Xcode ≥ 15 e iOS ≥ 13.

  1. Instalar y abrir Xcode una vez
  2. Aceptar licencia y seleccionar Xcode
  3. Descargar un runtime de simulador
  4. Confirmar las herramientas activas

Fuente: Apache Cordova, guía de iOS (matriz 8.x).

Aclare que macOS no basta por sí solo: se necesita Xcode completo, no únicamente Command Line Tools. El mínimo de Cordova no promete que esa versión cumpla siempre las reglas vigentes de publicación de Apple.

Dependencias nativas en iOS

14 / CocoaPods

CocoaPods resuelve dependencias nativas que pueden requerir los plugins en el proyecto iOS.

Matriz 8.x: CocoaPods ≥ 1.16.

  1. Instalar CocoaPods compatible
  2. Agregar ios@8.1.0 al proyecto
  3. Revisar cordova requirements ios
  4. Abrir el workspace generado si hace falta

Fuente: Apache Cordova, guía de iOS; anuncio cordova-ios 8.1.0.

CocoaPods no es un paso decorativo: ayuda a integrar código nativo de plugins. La documentación antigua conserva un mínimo menor, pero aquí se usa el de la matriz 8.x. El workspace generado es relevante para Xcode; no se abre ni se compila durante esta exposición.

Simulador y iPhone no son lo mismo

15 / destino

El simulador permite recorrer la app; un dispositivo físico añade firma, confianza y comportamiento real.

Elija el runtime o el iPhone antes de ejecutar run.

  1. Simulador: seleccionar runtime disponible
  2. Dispositivo: conectar y elegir un Team
  3. Activar firma automática y bundle ID
  4. Atender Developer Mode y confianza

Fuente: Apache Cordova, guía de iOS; Apple Developer Support.

El simulador no sustituye el hardware: permisos, rendimiento y algunos servicios se comportan distinto. Para iPhone, Xcode suele ser la ruta más clara para la primera firma. ios-deploy corresponde al dispositivo físico ya firmado, no al simulador ni a la firma.

Checklist para iniciar sin sorpresas

16 / cierre

El objetivo no es instalar todo a la vez, sino dejar lista la ruta de la plataforma elegida.

Empieza por Android o iOS; comparte solo Node, npm y la CLI.

  1. Node, npm y CLI compatibles
  2. Proyecto y plataforma definidos
  3. SDK o Xcode con rutas correctas
  4. Plugins opcionales revisados
  5. Destino de prueba elegido

Fuentes: guías oficiales de Cordova para CLI, Android e iOS.

Cierre con una recapitulación de aproximadamente un minuto. Esta presentación completa dura entre 10 y 15 minutos si se dedica cerca de 35 a 45 segundos a cada diapositiva y un poco más a Android e iOS. Reitere el límite: aquí se explicó el proceso, no se ejecutaron Cordova, la app, builds, emuladores, simuladores ni dispositivos.

Consultar antes de asumir

17 / fuentes

Los requisitos cambian por versión y plataforma. La documentación oficial es el punto de partida cuando una pieza no coincide.

Una versión mostrada o un comando listado no prueban que una instalación funcione.

  1. Guía CLI de Apache Cordova
  2. Guía Android y su matriz técnica
  3. Guía iOS y su matriz técnica
  4. Documentación de cada plugin

Fuentes: cordova.apache.org/docs/en/latest/guide/cli/, /platforms/android/ y /platforms/ios/.

Termine con una invitación a consultar la documentación de la versión elegida antes de resolver un problema. Esta slide deja clara la frontera entre la guía y una verificación real: se explicó el proceso, pero no se ejecutaron Cordova, la app ni herramientas nativas.
